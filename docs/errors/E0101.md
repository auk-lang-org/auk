# E0101: module name collides with a dependency

A file `src/json.duck` makes a module `json`, and the package also depends on a package named
`json`. Since `json.` would then be ambiguous, Duck rejects the clash instead of picking one.

## Wrong

The project depends on `json` (installed by `quack install`) and also has `src/json.duck`:

```toml quack.toml
[package]
name = "app"
version = "0.1.0"

[deps]
json = "^0.1"
```

```duck src/json.duck
pub fn pretty(s: str): str = s
```

```duck .quack/json/src/lib.duck
pub fn parse(s: str): int = s.len()
```

```duck
fn main() { print(json.pretty("[1]")) }
```

## Fixed

Drop the dependency you don't use from `quack.toml` (or rename `src/json.duck`):

```toml quack.toml
[package]
name = "app"
version = "0.1.0"
```

## Common causes

- A helper module named after a library you also depend on, or a dependency added later.
