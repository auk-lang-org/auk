# E0246: `return`, `?` or `fail` in a guard or constant

A `when` guard only decides whether a clause or arm applies; it must be pure and can't fail or
return. The same goes for a module constant's initializer.

## Wrong

```duck
fn positive(s: str): bool when int.parse(s)? > 0 = true
fn positive(_: str): bool = false
```

## Fixed

```duck
fn positive(s: str): bool when (int.parse(s) else 0) > 0 = true
fn positive(_: str): bool = false
```

## Common causes

- `?` on a fallible call in a guard: give a fallback with `else`.
- `return` inside a guard: compute the condition in the body instead.
- A fallible constant: compute it in `main` and pass it where it's needed.
