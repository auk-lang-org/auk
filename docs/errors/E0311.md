# E0311: `&` on an argument for a non-`var` parameter

`&x` marks an argument the callee may change, which only `var` parameters can do. This
parameter isn't `var`, so the `&` is misleading and rejected.

## Wrong

```duck
fn show(xs: [int]) { print(xs) }
fn main() {
  var a = [1]
  show(&a)
}
```

## Fixed

```duck
fn show(xs: [int]) { print(xs) }
fn main() {
  var a = [1]
  show(a)
}
```

## Common causes

- Using `&` to "pass by reference" for speed: Duck copies cheaply (copy-on-write).
- The callee was meant to change it: declare the parameter `xs: var [int]`.
