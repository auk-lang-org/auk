# Porting the runtime to Auk: the checklist

docs/self-host-plan.md, Phase 7; the target is the `raw` dialect, docs/lowlevel.md. This is
what each file of `runtime/c` needs from the dialect, and what does not translate line by line.
Measured 2026-11-18 (the C after "Write C that will translate to Auk later" was enforced).

## The rules the C now keeps (lowlevel.md, section 9)

- **No varargs calls** except in `cwrap.c`: fixed-argument wrappers for `open`, `shm_open`
  (varargs on macOS), `fcntl` (int argument), `ioctl` (pointer argument) and `snprintf` of
  one double (`%.*e`, `%.*f`, `%g`). Each becomes one `extern fn` with a fixed prototype.
  Integers and hex are formatted without libc (`str.c`: `auk__fmt_i64`, `auk__fmt_u64`,
  `auk__fmt_hex`, `auk__sb_u64`, `auk__sb_hex`); messages are built with the string builder
  and then copied into a fixed buffer (`auk__sb_take_into`, cut as `snprintf` cut),
  duplicated (`auk__sb_take_cstr`) or written to stderr in one write (`auk__sb_eprint`).
  Checked with the clang AST (`-Xclang -ast-dump`: no `DeclRefExpr` to a function whose type
  ends in `...)` outside `cwrap.c`). The runtime's own API has no varargs.
- **No `goto`** (the last six were `gui_host.c`'s `show`, now early returns).
- **No macros** but three that have to be: the include guard, `AUK_API` (a marker that
  expands to nothing; `export fn` in Auk) and `stack.c`'s `_GNU_SOURCE` (a glibc feature
  switch). Constants are `enum`s or typed `static const`s (`AUK_MAIN_STACK`, `STACK_GUARD`...).
- **No bit-fields** (none were left).
- **Unions: three, all `raw union`s:** `AukValue.u` (`auk_rt.h`: bool / i64 / f64 / three
  pointers; the pilot module, now `runtime/src/value.auk`, uses it), and in `gui.c` the two control-message
  buffers of `send_msg`/`read_full` (`union { struct cmsghdr h; uint8_t b[N]; }`: the
  `cmsghdr` member is there only for alignment).

## The shared foundations (runtime/src: `abi` and `cfacts`)

Every ported module imports two modules of the runtime package (2026-11-18):

- **`abi`** (`runtime/src/abi.auk`): every type of `auk_rt.h` as a `raw struct`/`raw union`
  (`abi.Header`, `Str` with its flexible `data`, `Arr`, `Map`, `ErrPayload`, `Err`, `Obj`,
  `Closure`, `Conn`, `Listener`, `Frame`, `Value`/`ValueU`, the `Opt*`/`Res*` structs,
  `StrBuf`, `ElemOps`, `Tmp`, `Panic`, `StrCase`, `DbgFrame`, `DbgCompiled`, `WireBuf`,
  `WireReader`, `WireMsg`), plus task.c's `Task` and chan.c's `Chan` (their pthread fields are
  `cfacts` types, so their offsets are per target); the enums as `raw let`s (`K_*`, `TRACKED`,
  `V_*`, `SB_SMALL`, `MAIN_STACK`, `TASK_STACK`, `WIRE_*`, `FFI_*`); the header's inline helpers
  (`is_handle`, `map_key`, `map_val`). Names drop the `Auk` prefix; fields keep C's names
  (`fn` is `func`). A `raw assert` on every size, alignment and field offset. The function-
  pointer typedefs are spelled out where used (no type aliases): the table is in the file's
  header comment.
- **`cfacts`** (`runtime/src/cfacts.<os>-<arch>.auk`, generated by `runtime/gen/cfacts.sh`,
  checked in for `macos-arm64`, `linux-arm64`, `linux-x86_64`): the C library's facts, from a C
  program compiled against the platform's headers with the runtime's feature macros
  (`-D_GNU_SOURCE` on Linux). Constants (`O_*`, `F_*`, `FD_CLOEXEC`, `S_IF*`, `PATH_MAX`,
  `TIOCGWINSZ`, `SEEK_*`, the `E*` the runtime uses, `SIG*`, `SA_*`, `SS_DISABLE`, `SIG_DFL`/
  `SIG_IGN` as addresses, `WNOHANG`, `AF_*`, `SOCK_*`, `SOL_SOCKET`, `SO_*`, `SCM_RIGHTS`,
  `IPPROTO_TCP`, `SHUT_*`, `MSG_PEEK`, `AI_*`, `POLL*`, `CLOCK_*`, `PROT_*`, `MAP_*`,
  `MAP_FAILED`, `PTHREAD_CREATE_*`, `RTLD_*`); the optional ones as `HAS_X` + `X` (0 where
  absent: `SO_NOSIGPIPE`, `MSG_NOSIGNAL`, `POSIX_SPAWN_CLOEXEC_DEFAULT`), which replaces the
  `#if defined(X)`s; opaque types by size and alignment (`PthreadT`, `PthreadMutex`,
  `PthreadMutexAttr`, `PthreadCond`, `PthreadCondAttr`, `PthreadOnce`, `PthreadAttr`,
  `PthreadKey`, `SigSet`, `PosixSpawnFileActions`, `PosixSpawnAttr`) and the static
  initializers `PTHREAD_MUTEX_INITIALIZER`, `PTHREAD_COND_INITIALIZER`, `PTHREAD_ONCE_INIT`
  as raw struct literals; struct layouts with the platform's field widths and padding
  (`Timespec`, `Timeval`, `Stat` with `st_atim/st_mtim/st_ctim` on both OSes, `Dirent`,
  `Winsize`, `Pollfd`, `Iovec`, `Msghdr`, `Cmsghdr`, `Sockaddr`, `SockaddrIn`, `SockaddrIn6`,
  `SockaddrUn`, `SockaddrStorage`, `Addrinfo`, `Sigaction` (one `sa_handler` field for the
  handler union), `StackT`, `DlInfo`); the signal context `uc_pc(uc)`, `uc_sp(uc)` (pointers
  to the interrupted PC/SP, per OS × CPU: stack.c's 13 `#if`s) and `si_addr(si)`; the C macros
  as functions (`wifexited`, `wexitstatus`, `wifsignaled`, `wtermsig`, `s_isdir`, `s_isreg`,
  `cmsg_align/len/space/data/firsthdr`); `errno()`/`set_errno`/`errno_ptr()` and C's
  `stdout()`/`stderr()`; the C typedefs' widths as comments (`mode_t: u16` on macOS). An "only
  on <os>" part at the end: `DISPATCH_TIME_*` (macOS); the ELF constants and `Elf64Ehdr`,
  `Elf64Shdr`, `Elf64Sym`, `elf64_st_type` (Linux, stack.c's symbol reader). Above that part,
  every platform's file declares the same items (checked).
- **Checked against C** by `runtime/test/abi/run.sh` (on each platform, in CI's containers
  too): `auk check` of both modules (every `raw assert` holds), then a probe built from the
  files themselves (`tables.awk`): an `auk build --lib` library returning every
  `raw.size_of`/`align_of`/`offset_of`, constant and initializer, linked with C that compares
  them with `sizeof`/`_Alignof`/`offsetof`, the macros and the bytes of the initializers (the
  real `auk_rt.h`, task.c's struct and chan.c's as it was (now in `probe.c`), the system headers), and `probe.c`, which
  calls the functions (the `W*` macros over every 16-bit status, `CMSG_*`, the ucontext slots,
  errno, a `stat(2)` read through `cfacts.Stat`, a mutex made from the initializer, `abi`
  structs by value both ways, a function pointer in an `ElemOps`). It does not see a field's
  width where the width doesn't move an offset (`abi` is written by hand: an `i32` for an
  `i64` before a pointer would pass).

## What the dialect does not cover yet (decide before the port reaches these files)

**Status (2026-11-18):** items 1 (per-target files), 4 (`extern var`), 5 (intrinsics), 7
(`raw assert`) are in the dialect (lowlevel.md, section 7a); 2 and 3 are covered by `cfacts`
except as listed under "Still open" below; 6 and 8 need nothing new.

1. **Conditional compilation.** 30 `#if`/`#elif` lines choose by OS (`__APPLE__`,
   `__linux__`), CPU (`__aarch64__`, `__x86_64__`), byte order (`audio_out.c`), or an optional
   constant (`SO_NOSIGPIPE`, `MSG_NOSIGNAL`). The dialect needs a compile-time `if` on the target (or
   per-OS files): `stack.c` (13), `core.c` (5), `gui.c` (5), `heap.c`, `audio_out.c`,
   `gui_host.c` (2 each), `tls.c` (1).
2. **C library macros and per-OS constants.** `errno` (a thread-local reached through
   `__error()` on macOS, `__errno_location()` on glibc), `stdout`/`stderr` (`__stdoutp` /
   `stdout` globals), `PTHREAD_MUTEX_INITIALIZER`/`PTHREAD_COND_INITIALIZER`/
   `PTHREAD_ONCE_INIT` (static initializers of opaque, per-OS layouts), `CMSG_*` (`gui.c`),
   `WIFEXITED`/`WEXITSTATUS`/`WIFSIGNALED`/`WTERMSIG` (`core.c`, `testing.c`), `S_ISDIR`
   (`core.c`), `ElfW`/`ELFMAG` (`stack.c`, Linux), and every `O_*`/`F_*`/`AF_*`/`SIG*`/`SO_*`
   value, which differ between macOS and Linux. Each needs a `raw let` per OS or a small C
   accessor.
3. **System struct layouts** as per-OS `raw struct`s: `struct sigaction`, `stack_t`,
   `ucontext_t`/`mcontext_t` (macOS `__ss.__pc`/`__rip`, Linux `pc`/`gregs`), `msghdr`/
   `cmsghdr`/`iovec`, `sockaddr_un`/`sockaddr_storage`/`addrinfo`, `stat`, `winsize`,
   `timespec`, and opaque-size buffers for `pthread_*_t`, `posix_spawn*_t`, `jmp_buf`.
4. **Importing a C global.** `environ` (`core.c`, `gui.c`), `stdout`/`stderr`; the dialect
   has `export var` but no `extern var`.
5. **Overflow-checked and bit intrinsics.** `__builtin_add/sub/mul_overflow` (`rc.c` for
   `int` arithmetic, `pixels.c`, `gui.c`, `gui_host.c`), `__builtin_ctzll`/`clzll`
   (`arr.c`). Raw integers wrap, so these need `raw.add_overflow(a, b): (T, bool)`-style
   intrinsics (LLVM's `*.with.overflow`, `cttz`, `ctlz`).
6. **Function-local statics** (`static` inside a function: `rc.c`, `core.c`, `gui.c`,
   `pixels.c` x2, `trace.c` x3) become module-level `raw var`s.
7. **`_Static_assert` / `offsetof`** (`auk_rt.h`, the layouts the compiler assumes):
   `raw assert` with `raw.offset_of`, as section 4 plans.
8. **`_Noreturn`** (panics, `auk__catch_throw*`): a `never` result.

### Found writing `abi` and `cfacts` (fixed since, lowlevel.md 7a)

Another module's `pub raw let` is a constant (`raw var lock: cfacts.PthreadMutex =
cfacts.PTHREAD_MUTEX_INITIALIZER`); `raw type` aliases name `mode_t` & co. per platform and the
function-pointer typedefs; `raw.size_of`/`align_of`/`offset_of` need no `uses raw`; an
out-of-range literal in a constant is E0210; `int` and `i64` mix. What the package uses from a
per-target module is checked against every target's variant (E0422), so the "only on <os>"
parts may stay.

- **Not in `cfacts`** (not header facts, or not expressible): `environ` (the same symbol on
  both OSes: an `extern var` in the module that needs it); `sigemptyset`/`sigaddset` (libc
  functions on both: call them); `FD_SET` (unused); `dispatch_*`/`nw_*` enum values and block
  types (tls.c's own declarations, lowlevel.md section 10); OpenSSL and PulseAudio constants
  (defined by the C files themselves, not taken from headers); `INFINITY` (a float literal);
  `jmp_buf` (the dialect's `raw.JmpBuf`, asserted at least as big as the platform's).

## Found by the pilot (`value.c`, 2026-11-19)

How a module moves: write `runtime/src/<module>.auk` (it is part of the package as soon as it
exists: `auk build --lib` compiles every module of `src/`), delete `runtime/c/<module>.c` in the
same commit (a C definition and an `export fn` of one name must never both be linked), keep
`auk_rt.h`'s declarations as they are, and run `./build.sh --check --test`. The layouts come
from `abi` (`abi.Value`, `abi.Str`, …); the rest of the runtime is reached through `extern fn`
prototypes over raw types (`void *` for the runtime's own pointer types: the prototype parser
doesn't know `AukStr`).

What the dialect lacked, or does differently from C:

1. **C string constants:** none, so the panic messages and tag names had no spelling. Added
   (lowlevel.md 7a): a string literal where a `raw.Ptr<u8>` is expected is a C string.
2. **Addresses in raw initializers** (`raw.fn_of(f)` in an `export var`'s initializer): fixed
   (lowlevel.md 7a: relocations, so `export var auk_ops_value: abi.ElemOps = abi.ElemOps {
   retain: raw.fn_of(f), … }` is a constant table).
3. **`never` is core's only:** fixed; `never` is a type of the runtime package (C `void`).
4. **`()` results are `i8`:** fixed; C `void`.
5. **`match` can't name a `raw let`:** fixed for the module's own integer `raw let`s (another
   module's: compare in a guard).
6. **Parameters have no address:** fixed.
7. **Calls named `auk_retain`/`auk_release`** are compiled as the compiler's reference-counting
   fast path (inline atomics, `auk__free_last` on the last reference), not as calls: equivalent,
   but `rc.c`'s port defines those two, and must not rely on calls to them being calls.
8. **The target triple:** auk names LLVM's default (`arm64-apple-darwin27.2.0`), clang its
   normalized form (`arm64-apple-macosx27.2.0`); `llvm-link` warns (build.sh filters it). Left
   as is: the `macosx` form carries a deployment version, which LLVM's code generation reads
   (libcall availability), so switching isn't a no-op on generated code.

## Found by the 7c port of `err`, `catch`, `pixels` (2026-11-19)

The three moved as the pilot did (same names and symbols, C's messages byte for byte; output of
a program over every `pixels` entry point, `AUK_GUI_TRACE=1` reports included, identical before
and after; the hot loops (fill, blend, composite, blit_mask) as fast as the C). New findings:

1. **Fixed** (2026-11-19, lowlevel.md 7a "Uninitialized locals": `var x: T`; catch, arr, map, chan, str and str_fmt's integer paths use it): **No `var` without an initializer:** `var fr: CatchFrame` is E0020, so C's uninitialized
   `CatchFrame fr` (a 320-byte `jmp_buf`) is a zeroed literal. In the `optnone` function that
   calls `raw.setjmp`, the literal goes through two temporaries (a memset and two 328-byte
   copies), so the non-panicking `catch` cost 30 ns against C's 8. `catch.auk` splits
   `auk__catch_run`: the optimized half makes the frame (one memset), a private `optnone`
   `run_at` calls `raw.setjmp`; 18 ns. The frame stays in the caller's memory, at the bottom of
   its stack frame, with `run_at`'s ~200 bytes below it: inside the 512 bytes stack.c's
   `redirect` leaves under the recovery point.
2. **Thread-locals in `optnone` code** are reached through the TLV getter on each access (macOS):
   the address is kept in a callee-saved register across `_setjmp`, which `_longjmp` restores.
   Fine, but each `raw thread var` touched there is a call.
3. **The same C prototypes in every module** (`auk__xmalloc`, `strlen`, `auk__sb_put_cstr`, …):
   no shared module of the runtime's own C functions yet. When `str`, `arr` and `rc` move, these
   `extern fn`s name functions the same package then defines as `export fn`s: **that breaks**
   (found by the `stack` port, below): drop the `extern fn`s and call the module.
4. Known ones met again: `never` (`auk__panic_sb`, `auk__catch_throw` are `()` with
   `raw.unreachable()` after the calls), a literal on the left of a fixed-width operator
   (`u32(255) - sa`), `match` on raw constants (none needed), C's `continue` in a counted loop
   (a `while` whose body is an `if`).

## Found by `copy`, `heap`, `chan`, `ffi` (Phase 7c, 2026-11-19)

The four moved the same way as the pilot (`runtime/src/copy.auk`, `heap.auk` with
`heap_os.<os>.auk`, `chan.auk`, `ffi.auk`; their C files deleted). What they ran into:

1. **A local can't share a module's name** (E0116, "`heap.` is ambiguous"): once `heap.auk`
   and `copy.auk` exist, a local `heap` or `copy` followed by `.` is refused in every module of
   the package. heap.c's `heap` locals are `hp`; copy.c's `copy` function-pointer locals `cp`.
   Every future module name (`str`, `map`, `arr`, `task`, …) takes the name from locals.
2. **`if` with a literal first arm is `int`:** `let cap = if c.cap == 0 { 8 } else { c.cap * 2 }`
   is E0200 (`int` vs `i64`): the literal doesn't take the other arm's type. Annotate the local
   (`let cap: i64 = …`).
3. **Fixed** (2026-11-19, lowlevel.md 7a "Uninitialized locals": `var x: T`; catch, arr, map, chan, str and str_fmt's integer paths use it): **No fixed-array locals:** `char buf[32]` (ffi.c's messages and `"0x"` buffer) is a local of
   a one-field `raw struct Buf32 { b: [u8; 32] }`, passed as `raw.cast(raw.addr_of(&buf))`.
4. **Fixed** (2026-11-19, lowlevel.md 7a "Uninitialized locals": `var x: T`; catch, arr, map, chan, str and str_fmt's integer paths use it): **No uninitialized locals:** `AukTmp tmp;` (264 bytes, chan.c's send and receive) is
   `var tmp = abi.Tmp {}`, zeroed on every call where C left it uninitialized (a 264-byte
   memset per send/recv; not visible in the benchmark below).
5. **Calls between ported modules are direct** (`heap.auk__heap_switch(…)`,
   `copy.auk__copy_elem(…)`): an `export fn` another module calls must be `pub export fn`
   (E0120 otherwise). Direct calls inline (chan's heap switches become TLS stores); an
   `extern fn` of a symbol another module of the package defines would not.
6. **Per-OS calls in a small module:** `malloc_size` (macOS) / `malloc_usable_size` (glibc) are
   `heap_os.macos.auk` / `heap_os.linux.auk` (one `pub fn usable_size`), the loader's per-target
   files, instead of two copies of heap.auk.
7. **Reading a `raw thread var` needs no effect** (E0411 "declares `raw` but doesn't use it" on
   `auk__heap_current`); `raw.atomic_*`, `raw.field_addr`, `raw.cast` do.
8. **`time_t`/`suseconds_t` widths differ** (cfacts' `Timeval.tv_usec` is `i32` on macOS, `i64` on
   Linux): `i64(now.tv_usec)` reads it on both.
9. Not hit: static `PTHREAD_*_INITIALIZER`s (chan.c and heap.c call `pthread_*_init` on each
   new object, so no constant initializer is needed); `never` (the `_Noreturn` panics are
   followed by `raw.unreachable()`, as in value.auk); `match` on raw constants (ffi.c's
   `switch (kind)` is `if`/`else if` over `abi.FFI_*`, as the pilot did); parameters' addresses
   (ffi.c's `memcpy(&v, …)` of a parameter goes through a `var` copy). The element-ops tables
   that point at copy.auk's `auk__*_copy_elem` stay C in `rc.c` (no addresses in initializers).

**Sanitizers:** `ASAN=1`/`TSAN=1 sh runtime/c/test/run.sh` instrument the C half; the Auk
half's own loads, stores and atomics are invisible to them (its `pthread_*`, `malloc`/`free`
calls are still intercepted, so locks and frees made from Auk code are seen). `SAN_AUK=1` (new)
instruments the Auk half too: `auk build --lib --bc`, every function given `sanitize_thread`
(or `sanitize_address`), LLVM's `tsan`/`asan` pass with `opt`, `clang -c`. It works: with
auk_chan_close's lock removed on purpose, `SAN_AUK=1 TSAN=1 … conc_chan` reports the race
between `auk_chan_close` and `chan_recv` (Auk frames by name); the real modules are clean under
`SAN_AUK=1 TSAN=1` (conc) and `SAN_AUK=1 ASAN=1` (all 72). A compiler flag that sets the
attribute itself would replace the `sed` (self-host-plan 7c, "ASan/UBSan equivalent").

## Found porting `str.c` (2026-11-19)

`str.c` (1556 lines) is `runtime/src/str.auk` (strings, UTF-8, the builder, the show budget,
searching, parsing) and `runtime/src/str_fmt.auk` (numbers to text, the shortest float, quoting,
format specs), line by line: every function under its C name, the same algorithms, output
byte-identical (golden against the C build: 0 differ in every mode). Its two thread-locals are
`raw thread var`s; `auk_trace_live` is an `extern var` read with `raw.atomic_load`. Small safe
functions are `inline export fn` (`auk_str_len`, `auk_str_eq`, `auk_str_concat`, `auk__str_raw`,
`auk__sb_put`, `auk_sb_str`, `auk_sb_int`, `auk_sb_finish`, `auk_str_from_int`, the `auk_char_*`,
…). `auk_ops_str`'s element functions moved from `rc.c` to `str.auk` (`auk__str_elem_eq/cmp/
hash/show`; the table stays in `rc.c`, as `auk_ops_value` in `value_ops.c`).

More of what the dialect lacks (the pilot's list above still holds; 3, 4, 5 were hit again:
`auk__panic_sb`'s callers say `raw.unreachable()`, `quote_char`'s `switch` is an `if` chain):

9. **An `extern fn` of a symbol another module of the package exports is renamed:** value.auk's
   `extern fn auk_str_lit(…) = "…"`, once str.auk defines `export fn auk_str_lit`, became a call
   to an undefined `auk_str_lit.75`. So every `export fn` here is also `pub`, and other modules
   call it through its module (`str.auk_str_lit(…)`, `str_fmt.auk_str_quote(…)`); value.auk does.
   **Every module ported in parallel that declares one of str.c's functions as an `extern fn`
   must do the same** (or the compiler must resolve such an `extern fn` to the definition).
10. **An `extern var` may be declared by one module only:** a second declaration of
   `auk_ops_str` became `auk_ops_str.1` (undefined), and `raw.addr_of(&other.var)` can't name
   another module's `extern var` (E0102). str.auk declares `auk_ops_str`, `auk_ops_char`,
   `auk_ops_int` and offers `str.ops_str()`; value.auk uses it.
11. **Fixed** (2026-11-19, lowlevel.md 7a "Uninitialized locals": `var x: T`; catch, arr, map, chan, str and str_fmt's integer paths use it): **No uninitialized locals, no array literals:** `var buf: [u8; 24]` needs a value and
   `[0; 24]` doesn't parse, so C's `char buf[24]` is a raw struct `Bytes24 { b: [u8; 24] }`,
   `var buf = Bytes24 {}` (zeroed: an extra `memset` C doesn't do; 24 bytes on the integer
   paths, 2048 in `auk__panic_sb`).
12. **`p.int()` is `int`, whose arithmetic is checked:** `at.int() - hay.int()` compiled to a call
   to `auk_sub` (overflow panic) in raw code. Convert first: `i64(at.int()) - i64(hay.int())`.
13. **Thread vars need no `uses raw`** (an `extern var` does): the four show-budget accessors
   were flagged E0411 for declaring it.
14. **Field loads through `raw.Ptr<abi.Str>` are `align 4`** in the IR (`load i64, … align 4`
   for `len_bytes`), where the struct is 8-aligned: harmless on arm64, worth fixing in codegen.

**Performance** (Apple M-series, the machine shared with other builds, load 30–80: so CPU
cycles from `/usr/bin/time -l`, A/B interleaved, 11–15 runs each, medians; an A/A control spread
±1.5% on medians; instructions retired where it decided): bench/perf `strings` −1%, `hashmap`
−2%, `sort` +1%, `trees` 0%; a micro-benchmark of hot string ops: `concat` −2%, `interp` −3%,
`slice` +2%, `chars` −2%, `split` −1%, `find` +2–3% (+1.3% instructions), int to str and back
+0–5% (+1.8% instructions: the zeroed digit buffer, 11), float to str 0%, `upper`/`lower`/`trim`
0%, `auk check` of the compiler −1%. Slower beyond the noise, both at the C/Auk boundary, and
both go when the C callee moves to Auk (one module: Auk calls Auk inline):
- **`s += x` (`auk_str_append`) +9% cycles (+6–13% over the runs), +4% instructions:** in C's one translation unit
  `auk__heap_usable` (heap.c) inlined into it as a `malloc_size` call; from Auk it is a call into
  C that makes the call. Measured: with `malloc_size` called inline, +4–5%. Likewise
  `auk__alloc` (rc.c) is now one call level more in every string allocation inside the runtime.
- **A `str`-keyed map lookup** was +4–5% cycles while rc.c's `str_eq`/`str_hash` wrappers called
  `auk_str_eq`/`auk_str_hash` across the boundary; with the wrappers in str.auk it is −4%
  instructions, cycles within noise (minimums equal, medians +0–5% with the load).
  `arr.c`'s string-sort fast path (`ops == &auk_ops_str`) still calls `auk_str_cmp` across it.

`auk build` inlines more string functions than before (with the C bitcode `auk_str_len`,
`auk_str_byte_len`, `auk_str_cstr` were folded aliases or not inlined; `auk_sb_str`,
`auk_sb_finish`, `auk_str_eq` mostly calls): in the compiler, calls to `auk_sb_str` fell from
2066 to 300, `auk_sb_finish` 1808 to 219, `auk_str_eq` 898 to 155, and its text grew from 4.20 to
4.86 MB, with `auk check` 1% faster. Every program also links ~16 KB more: the Auk half is one
object, so a program that uses any of it gets all of it.

## Found by the 7c port of `stack`, `testing`, `compiler`, `auk_ops_value` (2026-11-19)

Same rules as before (symbols, C ABI, messages byte for byte; `auk_rt.h`'s declarations
untouched). `value_ops.c` is gone: `auk_ops_value` is an `export var` of `value.auk` built from
`raw.fn_of`s of private functions (the `auk__value_elem_*` symbols are gone; the copy slot is a
private wrapper over copy.c's `auk__value_copy_elem`, since a constant's `raw.fn_of` names an
Auk function, not an `extern fn`). New findings:

1. **An `extern fn` for a symbol the package defines was renamed, not merged** (fixed since:
   "codegen: a runtime symbol the package defines is called, not redeclared"; a seed older
   than that fix still has it). `stack.auk`
   declared `extern fn auk__catch_active(): i32 = "int auk__catch_active(void)"` while
   `catch.auk` defines it as an `export fn`: in the one LLVM module of `auk build --lib` the
   declaration became `@auk__catch_active.130` (likewise `auk__catch_top_addr.145`,
   `auk__catch_throw_overflow.131`, and catch's `extern fn auk__stack_overflow_loc` became
   `.14`): no error from `auk`, an undefined symbol at the first link (`nm` shows
   `U _auk__catch_active.130`). Fix used: call the defining module by path
   (`recover.auk__catch_active()`, `stack.auk__stack_overflow_loc()`), the `export fn` marked
   `pub` (`pub export fn` works); still the preferred style for symbols already in Auk. **The
   same for `extern var`s:** two modules declaring `extern var
   auk_ops_float` link to `auk_ops_float` and `auk_ops_float.1` (identical `extern fn`s in
   several modules, `strlen` & co., are merged fine). compiler.auk takes value.auk's (`pub
   extern var`) as a constant address: `raw let OPS_FLOAT: raw.Ptr<abi.ElemOps> =
   raw.addr_of(&value.auk_ops_float)` (`raw.addr_of(&m.g)` of another module's global works
   in a constant only); with the fix a plain `extern var` would do too.
2. **The module `catch` can't be named:** `catch` is a keyword, so `catch.f()` is a parse error
   (E0021) and no other module could call it. `catch.auk` is now `recover.auk` (same contents
   and symbols; `auk__catch_throw_overflow` is `never` now).
3. **A local hides a module of the same name** (E0116: `let err = cfacts.stderr()`, then
   `err.auk_err_show(e)`): rename the local (`errf`).
4. **Per-CPU code has no file kind of its own:** variants are `<os>-<arch>`, `<os>` or plain, so
   stack.c's one CPU difference (on x86-64 `redirect` leaves SP 8 below 16-byte alignment, where
   a `call` would have pushed the return address) is a module: `cpu.auk` (AArch64,
   `RET_SLOT = 0`) and `cpu.linux-x86_64.auk`/`cpu.macos-x86_64.auk` (8). The per-OS parts
   (stack bounds: `pthread_get_stackaddr_np` vs `pthread_getattr_np`; the Linux `.symtab`
   reader) are `stackos.macos.auk`/`stackos.linux.auk`; `stackos.SymBuf` (the reader's buffer)
   is 1 byte on macOS, so the handler doesn't zero 256 unused bytes there. The 13 `#if`s are
   gone: `cfacts.uc_pc`/`uc_sp` (pointers into the context, read and written) cover the four
   OS × CPU register slots.
5. **The signal handler and the `pthread_once`/`pthread_create` start routines are private
   functions** given to C by `raw.fn_of` (numbers and raw pointers only, so they have C
   addresses; no new exported symbols). A private function returning `()` returns an `i8` in
   the IR (C ignores it); `export fn`s and `raw.Fn` calls are C's `void`. The handler allocates
   nothing (checked in the IR: its calls are `strlen`, `strncmp`, `dladdr`, `signal`, `write`,
   `_exit`, `_longjmp`, `auk__trace_on_overflow` and stdio's `ftrylockfile`/`fflush`, as the C).
6. **`pid_t` isn't known to the prototype parser** (E0040; `ssize_t`, `size_t`, `pthread_t`,
   `FILE *` are): `fork`, `getpid`, `waitpid` are declared with `int` (`pid_t` is `i32`).
7. **A call whose C result is unused** must be dropped explicitly when it ends a block whose
   value is `()` (`let _ = sigaction(…)`, or a helper like compiler.auk's `putc`); in the
   middle of a block it's fine.
8. C's `char buf[N]` locals are one-field raw structs (`raw struct NumBuf { b: [u8; 24] }`),
   zeroed (C left them uninitialized); `_Atomic bool auk_trace_live` is read as an
   `extern var … : u8` with `raw.atomic_load` (atomics take integers and pointers).

## Found porting `tls.c` (2026-11-19)

`runtime/src/tls.auk` holds what both platforms share (`check_args`, `valid_host`, the
"net.tls <host>:<port>" prefix, the Err builders); the sessions are a per-OS module,
`tls_os.macos.auk` and `tls_os.linux.auk`, each defining `auk_net_tls`, `auk__tls_read`,
`auk__tls_write`, `auk__tls_free`. (Not `tls.macos.auk`: the loader takes the most specific
variant of a module *instead of* the plain file, so shared code needs its own module, as
`heap`/`heap_os`.) Messages byte for byte as the C's (both backends' tables of reasons copied
verbatim; the C tests' and the runner's TLS checks pass, real hosts too).

macOS, the blocks (lowlevel.md §10, as the spike did, now in the runtime): `BlockHdr`,
`BlockDesc`, `BlockDescCD` raw structs; `_NSConcreteStackBlock`/`_NSConcreteGlobalBlock` are
`extern var … : [u8; 0]` (their addresses are the `isa`s), `_nw_content_context_default_stream`
an `extern var … : raw.Ptr<()>` (its value); the TCP configure block is a global literal (a `raw
var` whose `invoke`/`descriptor` are relocations); TLS configure, verify, state handler and
`dispatch_sync`'s outcome reader are stack literals without helpers (they capture the session,
which lives until `auk__tls_free` waits for the cancelled state); receive and send completions
are stack literals with copy/dispose helpers that retain/release the op (`NwOp.refs` starts at 1,
the caller's; each framework copy holds one), replacing tls.c's hand-counted `refs = 2`; the
data applier is a stack literal (`dispatch_data_apply` doesn't copy). Invoke functions and
helpers are private functions given by `raw.fn_of`. The block-taking SDK functions, and every
other Network/Security/CoreFoundation/dispatch call, are `extern fn`s with `void *` objects
and blocks; the SDK's enum values are `raw let`s (checked against the headers with a C probe
when written: `nw_error_domain_*`, `nw_connection_state_*`, `errSec*`,
`kCFStringEncodingUTF8`, `tls_protocol_version_TLSv12`). Linux: libssl's entry points are a
raw struct of `raw.Fn`s in a `raw var` filled by `dlsym` under `pthread_once` (a private
`ssl_load` by `raw.fn_of`); each call copies the pointer to a local first (a function pointer
in a global's field isn't callable in place).

Gaps hit:

1. **A C string literal isn't a constant** (E0421 in a global's initializer), so a block
   descriptor can't point at its signature string: the literals carry no
   `BLOCK_HAS_SIGNATURE` and null signatures (Clang's encodings are comments). Nothing tls
   hands blocks to reads them (the spike's `SPIKE_NO_SIGNATURE` run showed it first; the runtime
   now runs that way). A string literal as a constant (a private C string with a relocation)
   would restore them.
2. **`{` in a string literal is interpolation**: block signatures (`^{nw_error=}`) need `{{`/`}}`
   wherever they're spelled as strings.
3. **`when` is a keyword** (a parameter of `dispatch_time`).
   A string literal passed to a generic intrinsic (`raw.copy(b, "protocol error", 15)`, whose
   source is `raw.Ptr<_>`) stays a `str` (E0200/E0419): the C-string rule needs a concrete
   `raw.Ptr<u8>` expected, so it goes through a typed local. Found only by the Linux build
   (the other target's file is parsed on every host, but only type-checked on its own).
4. Known ones met again: no fixed-array locals (`char ports[24]`, OpenSSL's `char buf[256]`,
   inet_pton's `addr[16]`: one-field raw structs), a local can't share a module's name (C's
   `err`, `tls`, `str` locals renamed), a function pointer stored in a global struct's field is
   called through a local, `auk__xcalloc`/`auk__xmalloc` are `raw.alloc` + `raw.fill` (abort on
   failure; rc.c's `oom` message isn't printed), and `err.auk`'s `auk__err_errno` is now `pub`
   so tls calls it by path. The C functions still in C (`task.c`'s `auk__on_task`,
   `auk__task_cancelled`, `auk__check_cancel`, `auk__wait_fd`; `core.c`'s `auk__conn_new`,
   `auk__bytes_to_arr`, `auk__tcp_connect`; `rc.c`'s `auk_release`) are `extern fn`s: once
   those modules move, calls by path are the preferred style (codegen now merges an `extern fn`
   with the package's definition either way).
5. A cancelled wait called `auk__check_cancel` and then fell through in the C (it never returns
   then); here a `raw.trap()` follows it, so the freed session is never touched.

`build.sh` and `runtime/c/test/run.sh` compile the C half with `-fno-blocks` on macOS (was
`-fblocks`; no C file uses blocks now: clang enables them by default on Darwin, so the flag
makes it a compile error to start again).
